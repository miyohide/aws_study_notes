## SageMaker AI の各サービス・機能

### データ準備・ラベリング

#### Amazon SageMaker Data Wrangler

- 目的：データの視覚化、クレンジング、変換
- 参考：[Amazon SageMaker Data Wrangler](https://aws.amazon.com/jp/sagemaker-ai/data-wrangler/)

#### SageMaker Ground Truth

- 目的：トレーニングデータに対してラベリング作業を提供する。自動でも人手でも実施できる
- キーワード
  - プライベートワークフォース：選択したワーカーのグループ。特定のタスクに知識が豊富なメンバーで構成できる
  - 精度向上のための機能
    - 注釈統合
    - 注釈インターフェイス
- 参考：[Amazon SageMaker Ground Truth](https://aws.amazon.com/jp/sagemaker-ai/groundtruth/)

#### AWS Glue DataBrew

- 目的：ビジュアルデータ準備ツール。データのクリーニングと正規化をGUI操作（ノーコード）で実装できる
- 参考：[AWS Glue DataBrew](https://aws.amazon.com/jp/glue/features/databrew/)

#### AWS Glue Studio

- 目的：ETLジョブの作成・実行をGUIで組み立てられる

### 特徴量管理

#### SageMaker Feature Store

- 目的：特徴量のフルマネージドサービス
- キーワード
  - オンライン推論：リアルタイム推論向け
  - オフラインモデルのトレーニング：バッチでの学習向け
  - GetRecord API：特定の特徴量を取得。リアルタイム推論での利用に最適
  - PutRecord API：新しい特徴量を即座に登録
- 参考：[Amazon SageMaker Feature Store](https://aws.amazon.com/jp/sagemaker-ai/feature-store/)

### トレーニング・デバッグ

#### SageMaker Debugger

- 目的：機械学習トレーニングジョブからのモデル出力をリアルタイムでデバッグし、収束しない問題を検出する

### ワークフロー構築

#### SageMaker Pipeline

- 目的：ワークフロー全体を構築
- 参考：[Amazon SageMaker Pipelines](https://aws.amazon.com/jp/sagemaker-ai/pipelines/)

##### Lambda step と Callback step の違い

パイプラインにカスタム処理を組み込むためのステップ。実行方式が異なる。

| 項目 | Lambda step | Callback step |
| --- | --- | --- |
| 実行対象 | AWS Lambda 関数を同期実行する | パイプライン外の処理（SageMakerが直接対応しない処理）を組み込む |
| 動作 | Lambda を呼び出し、結果が返るまで待つ。返り値を後続ステップで使える | メッセージをSQSキューに送り、パイプラインは一時停止して待機する |
| 再開方法 | Lambda の処理が終われば自動で次へ進む | 外部システムが処理後に `SendPipelineExecutionStepSuccess` / `Failure` API を呼んで再開させる |
| 実行時間 | Lambda の上限（最大15分）に収まる短い処理向け | 時間のかかる処理や非同期処理も待てる |
| 向いているケース | 軽量な前後処理、条件分岐用の値の算出、簡単なデプロイなど | SageMaker外のカスタム処理を任せ、完了通知を待ちたいとき |

- Lambda step：短くその場で完結する処理向け。
- Callback step：時間のかかる処理や外部システムに任せる処理向け。SQS経由で連携し、完了通知（API呼び出し）を待つ。

### モデルの監視・説明可能性

#### SageMaker Model Monitor

- 目的：デプロイ済みのモデルのパフォーマンスを継続的に監視し、異常検出時にアラートを出す
- キーワード
  - データドリフト監視：入力データの特徴がトレーニングデータと異なる場合に通知する
  - フォールバックメトリクス：本来見たいメイン指標が使えないときに、代わりに監視する予備の指標
    - モデル品質の評価には正解ラベル（グラウンドトゥルース）が必要だが、実際の結果は後から判明することが多く、すぐには精度やRMSEを計算できない
    - その間は、正解ラベルなしでも計算できるデータ品質メトリクス（入力データの分布変化＝データドリフト）をフォールバックとして監視する
    - 正解ラベルが揃ったら、本来のモデル品質メトリクスによる評価に切り替える

#### SageMaker Clarify

- 目的：データセットやモデルのバイアス検知、予測の説明可能性を提供
- 参考：[Amazon SageMaker Clarify](https://aws.amazon.com/jp/sagemaker-ai/clarify/)

#### SageMaker ML Lineage Tracking

- 目的：機械学習ワークフローの各ステップ（データ、処理ジョブ、トレーニング、モデル、エンドポイントなど）のつながりを自動で記録・追跡する
- ポイント
  - どのデータからどのモデルが作られ、どこにデプロイされたかという来歴（リネージ）をたどれる
  - モデルの再現性の確保、監査対応、ガバナンスに役立つ
- 参考：[Amazon SageMaker ML Lineage Tracking](https://docs.aws.amazon.com/sagemaker/latest/dg/lineage-tracking.html)

### その他の設定

#### メタデータ収集のオプトアウト（OPT_OUT_TRACKING=1）

- 概要：SageMaker AI はデフォルトで利用状況などのメタデータ（テレメトリ）を収集する。これを無効化したい場合は、環境変数 `OPT_OUT_TRACKING` に `1` を設定する
- 設定方法：トレーニングジョブ（create-training-job など）の環境変数に指定する

  ```json
  {
    "Environment": {
      "OPT_OUT_TRACKING": "1"
    }
  }
  ```

- ポイント
  - データのプライバシー要件が厳しい環境で、メタデータ送信を止めたいときに利用する
- 参考：[Data Privacy in Amazon SageMaker AI](https://docs.aws.amazon.com/sagemaker/latest/dg/data-privacy.html)

## 推論エンドポイント

### マルチモデルエンドポイント（MME）と マルチコンテナエンドポイント（MCE）の違い

1つのエンドポイントで複数のモデルを提供する仕組みだが、目的が異なる。

| 項目 | マルチモデルエンドポイント（MME） | マルチコンテナエンドポイント（MCE） |
| --- | --- | --- |
| 目的 | 同じフレームワーク・コンテナで、多数のモデルを効率よくホストする | 異なるフレームワーク・コンテナのモデルを1つのエンドポイントにまとめる |
| コンテナ | 1種類のコンテナを共有 | 最大15個の異なるコンテナ |
| モデルの数 | 数千規模まで可能 | コンテナ数に依存（最大15） |
| モデルの読み込み | 呼び出し時にS3から動的にロード（使わないモデルはメモリから退避） | 各コンテナは常時ロード済み |
| 呼び出し方法 | リクエストで対象モデルを指定 | リクエストで対象コンテナを指定、または直列に連結（推論パイプライン）できる |
| 向いているケース | 同種のモデルが大量にあり、コストを抑えたい | 異なる種類のモデルを1つのエンドポイントに集約したい |

- MME：多数の類似モデルを低コストで運用したいとき。使用頻度の低いモデルはメモリから退避されるため、リソースを節約できる。
- MCE：フレームワークが異なるモデル（例：TensorFlowとPyTorch）を同居させたいときや、複数モデルを直列でつなぐ推論パイプラインを組みたいとき。

## 機械学習の基礎

### 分類と回帰

- 分類：データが属するクラスを予測する（例：スパムかどうか）
- 回帰：連続する数値を予測する（例：今後の売上金額）

### 主要アルゴリズムの詳細

#### 因数分解機（Factorization Machines）

- 概要：「ユーザーと商品」「ユーザーと広告」など、複数の特徴量の組み合わせから予測する線形モデル。行列分解を用いて特徴間の相互作用を学習する
- 特徴
  - データが疎（sparse）になりやすいケースでも扱える
  - 特徴量同士の相互作用を効率よく学習できる
- ユースケース：推薦システム、広告のクリック予測

#### 線形学習（Linear Learner）

- 概要：線形回帰（数値予測）とロジスティック回帰（分類）の両方を扱えるSageMaker組み込みアルゴリズム。複数のモデルを並列に学習し、最も良いものを自動的に選ぶ
- 特徴
  - 数値予測（回帰）と分類のどちらにも使える
  - 大規模データでも高速に学習できる
  - 前処理として特徴量の正規化を自動で行える
- ユースケース：売上予測、顧客離脱（チャーン）予測、需要予測など、入力と出力がおおむね線形の関係にあるケース

#### XGBoost

- 概要：勾配ブースティング決定木（GBDT）を用いたアルゴリズム。弱い決定木を順番に追加し、前の木の誤りを次の木が補正していくことで高精度なモデルを作る
- 特徴
  - 表形式（テーブル）データで高い精度を出しやすく、コンペや実務で広く使われる
  - 欠損値をそのまま扱える
  - 正則化が組み込まれており過学習を抑えやすい
- ユースケース：クレジットスコアリング、不正・詐欺検出、需要予測、ランキングなど

#### Object2Vec

- 概要：単語・文・アイテムなどのオブジェクトのペアの関係性を学習し、低次元の埋め込みベクトルに変換する汎用の埋め込みアルゴリズム
- 特徴
  - 2つのオブジェクトの関係（類似度など）を学習できる
  - 得られた埋め込みは、分類・推薦・類似検索など下流タスクの入力として使える
- ユースケース：文書分類、ユーザーとアイテムの関係予測（推薦）、類似アイテム検索

#### DeepAR

- 概要：RNN（再帰型ニューラルネットワーク）ベースの時系列予測アルゴリズム。多数の関連する時系列をまとめて1つのモデルで学習する
- 特徴
  - 複数の時系列を横断的に学習するため、単系列ごとに個別モデルを作るより精度が出やすい
  - 履歴の短い（新しい）系列でも、他系列から学んだパターンを活かして予測できる
  - 確率的予測（予測区間つき）が可能
- ユースケース：商品ごとの需要予測、店舗ごとの売上予測、電力・アクセス数の予測

#### PCA（主成分分析）

- 概要：高次元のデータを、情報をできるだけ保ったまま少ない次元に圧縮する教師なしの次元削減手法
- 特徴
  - 相関の強い特徴量をまとめ、分散が大きい方向（主成分）を軸に取り直す
  - 特徴量が多すぎる場合の前処理や、可視化のための次元削減に使う
- ユースケース：データの可視化、特徴量削減による学習の高速化、異常検知の前処理

#### K-Means

- 概要：データをあらかじめ指定したK個のクラスタ（グループ）に分ける教師なしのクラスタリング手法。各データを最も近いクラスタ中心に割り当てる
- 特徴
  - ラベルのないデータをグループ分けできる
  - クラスタ数Kは事前に指定する必要がある
- ユースケース：顧客セグメンテーション、画像の色圧縮、行動パターンのグループ化

#### KNN（K最近傍法）

- 概要：予測したいデータに近いK個の既存データを見て、多数決（分類）や平均（回帰）で結果を決めるシンプルな教師ありアルゴリズム
- 特徴
  - 学習時にモデルを作り込まず、予測時に近傍を探す
  - Kの値と距離の測り方が結果に影響する
- ユースケース：画像認識、レコメンド、異常検知

#### ランダムカットフォレスト（Random Cut Forest, RCF）

- 概要：データを木構造でランダムに分割していき、各データ点に異常スコアを付ける教師なしの異常検知アルゴリズム
- 特徴
  - 他と大きく外れたデータ（分割で早く孤立する点）ほど高い異常スコアになる
  - ストリーミングデータのリアルタイム異常検知にも対応
- ユースケース：ネットワーク侵入検知、不正取引検知、センサー異常やアクセス数の急変検知

#### seq2seq（Sequence to Sequence）

- 概要：入力の系列（シーケンス）を、別の系列に変換するエンコーダ・デコーダ構造のアルゴリズム。入力をエンコーダが1つのベクトルにまとめ、デコーダが出力系列を生成する
- 特徴
  - 入力と出力の長さが異なってもよい
  - 系列（文章・音声など）を別の系列に変換するタスク全般に使える
- ユースケース：機械翻訳、文章要約、音声のテキスト化

#### ロジスティック回帰（Logistic Regression）

- 概要：入力の線形結合をシグモイド関数などで0〜1の確率に変換し、その確率をもとに分類する線形モデル
- 特徴
  - 出力が確率として解釈できるため、しきい値で分類を調整できる
  - シンプルで学習が速く、結果の解釈がしやすい
  - SageMakerでは線形学習（Linear Learner）で分類を選ぶと利用できる
- ユースケース：スパムメール判定、購入・離脱の予測、疾病リスクの判定などの2値分類

## ハイパーパラメータチューニング

| 戦略                        | 探索方法                | 過去の試行結果を利用 |  並列実行 | 特徴                     | 向いているケース           |
| ------------------------- | ------------------- | ---------: | ----: | ---------------------- | ------------------ |
| **Grid Search**           | 全組み合わせを網羅           |          ❌ |     ○ | 指定したカテゴリ値の全組み合わせを試す    | 組み合わせが少ない、再現性重視    |
| **Random Search**         | ランダムに選択             |          ❌ | **◎** | 各試行が独立しているので大量並列実行しやすい | 試行回数を増やしたい、大規模探索   |
| **Bayesian Optimization** | 過去の結果から「良さそうな場所」を予測 |      **○** |     △ | 過去の結果を利用して次の候補を賢く選ぶ    | 学習コストが高く、効率的に探索したい |
| **Hyperband**             | 成績の悪い試行を早期終了        |          ○ | **◎** | 有望なモデルに計算リソースを集中       | 学習に時間がかかるモデル       |

### ベイズ最適化（Bayesian Optimization）

過去の試行結果をもとに「次に試すと良さそうなハイパーパラメータ」を推測しながら探索する手法。Grid Search や Random Search のように闇雲に試すのではなく、少ない試行回数で良い組み合わせにたどり着くことを狙う。

- 仕組み
  1. これまでの試行結果（ハイパーパラメータと精度の組み合わせ）から、精度を予測する代理モデル（サロゲートモデル、ガウス過程など）を作る
  2. 「良い精度が期待できそうな場所」と「まだ試していない未知の場所」のバランスを取りながら、次に試す候補を選ぶ（獲得関数を利用）
  3. 実際に学習して結果を得たら、その結果を代理モデルに反映して1に戻る
- 特徴
  - 過去の結果を活用するため、試行回数が少なくて済みやすい
  - 前の結果に依存するため、Random Search ほど大量の並列実行には向かない
- 向いているケース
  - 1回の学習コストが高く、試行回数をできるだけ抑えたいとき
  - SageMaker の自動モデルチューニング（AMT）でもデフォルトの戦略として利用できる

## データ前処理

### One-hot encoding

機械学習で扱いにくいカテゴリデータを、0と1の数値に変換する方法。例えば曜日というカテゴリデータを、カテゴリごとに列を作る。以下のような感じ。

| 曜日 | 月 | 火 | 水 |
| --- | --- | --- | --- |
| 月曜日 | 1 | 0 | 0 |
| 火曜日 | 0 | 1 | 0 |
| 水曜日 | 0 | 0 | 1 |

### Data Wrangler のカテゴリカルエンコード

カテゴリ（文字列などの分類値）を、機械学習モデルが扱える数値に変換する Data Wrangler の変換機能。多くのアルゴリズムは数値しか扱えないため、「赤・青・緑」や「東京・大阪」のようなカテゴリデータを数値化する。Data Wrangler ではGUIから主に次の2方式を選べる。

| 方式 | 変換内容 | 向いているケース | 注意点 |
| --- | --- | --- | --- |
| Ordinal encode（順序エンコード） | 各カテゴリに整数を割り当てる（例：赤→0、青→1、緑→2）。列は1つのまま | 低・中・高のように順序・大小の意味があるカテゴリ | 順序のないカテゴリに使うと、モデルが誤った大小関係を学習しやすい |
| One-hot encode（ワンホットエンコード） | カテゴリごとに列を作り、該当する列だけ1、他は0にする | 色や地域のように順序のないカテゴリ | カテゴリ数が多いと列が大量に増える |

- 使い分けの目安：カテゴリに順序があれば Ordinal encode、順序がなければ One-hot encode。
- One-hot encode は上記「One-hot encoding」と同じ考え方。

### 歪んだデータへの対処

分布が偏った（歪んだ）データを扱いやすい形に変換する方法。

- 対数変換：値の範囲が大きく右に裾を引く分布を、対数を取ることでなだらかにする
- ビニング：1つの特徴量を一定間隔に分割し、それぞれの区間を別の特徴量とみなして扱う（区間ごとに重回帰などを行う）

### 不均衡データへの対処（オーバーサンプリング／アンダーサンプリング）

クラスごとの件数に大きな偏りがある（不均衡な）データのバランスを取る方法。

- オーバーサンプリング：件数が少ないクラスのデータを増やす
  - 手法の一つに SMOTE（Synthetic Minority Over-sampling TEchnique）がある。k-NNアルゴリズムを用いて擬似データを生成する
- アンダーサンプリング：件数が多いクラスのデータを減らす

## 学習のテクニック

### 学習率

パラメータ（重みやバイアス）をどれぐらい変化させるかを表すハイパーパラメータ。

- 値が大きすぎると学習のスピードは上がるが、最適解に収束しない（振動または発散する）
- 値が小さすぎると収束しやすいが、収束までに時間がかかる

### 深層学習モデルの学習を安定させたい

学習率を小さく、ミニバッチを大きくする。

### オーバーフィッティング（過学習）とその対処

学習データに過剰に適合してしまい、未知のデータに対して期待する精度が出ない状態。対処方法として、以下を実施する。

- 正則化の制約を増やす
- ドロップアウトを増やす
- 次元圧縮
- レイヤーを減らして単純なモデルにする
- 学習率を小さくする

### 正則化（L1正則化・L2正則化）

過学習を抑えるために、損失関数へ重みの大きさに応じたペナルティ項を加える手法。ペナルティの計算方法によってL1とL2に分かれる。

| 項目 | L1正則化（Lasso） | L2正則化（Ridge） |
| --- | --- | --- |
| ペナルティ | 重みの絶対値の合計 | 重みの二乗の合計 |
| 重みへの影響 | 不要な重みを完全に0にする（スパースになる） | 重みを全体的に小さくする（0にはなりにくい） |
| 効果 | 特徴量の選択（自動的に重要な特徴だけ残す） | 重みの偏りを抑えて過学習を防ぐ |
| 適用ケース | 特徴量が多く、重要なものだけに絞りたいとき | 多くの特徴量をまんべんなく使いたい、多重共線性を抑えたいとき |

- L1正則化：不要な特徴量の重みが0になるため、実質的に特徴量選択として使える。特徴量が非常に多いケースに向く。
- L2正則化：すべての重みを均等に小さく抑える。特徴量間の相関（多重共線性）が強い場合に安定しやすい。
- 両方を組み合わせた手法として Elastic Net がある。

## モデルの評価

### 混同行列（Confusion Matrix）

| - | 実データ・正 | 実データ・負 |
| --------- | ------------- | -------------- |
| 予測・正 | 真陽性（TP） | 偽陽性（FP） |
| 予測・負 | 偽陰性（FN） | 真陰性（TN） |

正や負がそれぞれ正解／不正解を常に表現しているとは限らないことに注意。モデルにより検出したいほうを陽性と表現することが多い。

評価指標として、以下のものを認識しておく。

- リコール（再現率、真陽性率）= TP / (TP + FN)
  - 実際に陽性のデータのうち、どれだけ正しく陽性と判定されたか
  - 病気検出やスパム検出など **検出漏れを減らす** 場合に活用
- 適合率（精度）= TP / (TP + FP)
  - 陽性と予測した中で、本当に陽性の割合
  - 詐欺検出など **誤検知を減らす** 場合に活用

リコールと適合率はトレードオフになるため、両者の調和平均であるF1値を活用することが多い。

参考：[評価指標について](https://tech.ledge.co.jp/entry/metrics)

### シルエットスコア（シルエット係数）

クラスタリング（K-Meansなど教師なし学習）の結果がどれだけ良いかを評価する指標。各データ点について、同じクラスタ内のまとまりの良さと、他クラスタからの離れ具合を比べる。

- 各点のシルエット値：`s = (b - a) / max(a, b)`
  - a：同じクラスタ内の他の点との平均距離（小さいほど密にまとまっている）
  - b：最も近い別のクラスタの点との平均距離（大きいほど他クラスタから離れている）
- 値の範囲は -1 〜 1
  - 1 に近い：クラスタ内でよくまとまり、他クラスタから離れている（良い）
  - 0 に近い：クラスタの境界付近にある（どっちつかず）
  - マイナス：別のクラスタに割り当てたほうが良さそう（割り当てが不適切な可能性）
- 全データ点の平均がクラスタリング全体の良さを表す
- 主な使いどころ：K-Means のクラスタ数Kを決めるとき。複数のKで試し、スコアが最も高いKを選ぶ（同じ目的の手法にエルボー法がある）
